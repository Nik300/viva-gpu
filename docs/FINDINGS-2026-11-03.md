## Where we are
- `vivagpu=2` boot: the GPU powers up, `VivaGPUAccelerator` is published, Metal loads `VivaMTLDriver.bundle`.
- `backboardd` composes with our driver; SpringBoard starts; the user sees icons and a mostly correct dock.
- **Still broken:** parts of the screen stay black or update erratically, worst during animations. Cause: fragment
  jobs of `backboardd` that fail with **MMU read faults at garbage addresses** (job bus fault 0x48) and a few
  **3 s timeouts** (hard stop). ~32 faults + 2 timeouts per boot even with the latest driver.
- Phone tests (run with `viva-link.py run`): `compute` **8/8**, `phase3` 28/33, `uploads` 18/19, `phase1` crashes
  (sig 11), `translate` aborts (sig 6). `ca` (CARenderer scene, incl. backdrop blur, vibrancy, LA08 IOSurface
  contents, rendering into an IOSurface) renders **identically to the M1 reference** on the real Mali, no faults.

## The open problem: MMU faults in backboardd
- Addresses are the same across boots: `0x161f3980`, `0x402e3900`, `0xe61e3800`, `0xa21e4f00`, `0x3ee7e300`, `0xea43900`…
  The kernel prints them sign-extended (`0xffffe61e3800` = `0xe61e3800`).
- **Not the kernel, not BO lifetime:** with `VGPU_TRACE_BO=1` no fault address lies in any live, closed, created or
  imported BO (backboardd's BOs end around `0xd7b1000`). The GPU reads through a garbage pointer: most likely a
  descriptor (texture / sampler / attribute / blend) read from uninitialized memory.
- Fault status: translation fault, read, source 0x0060 / 0x0460, slot 0 (fragment). Some jobs time out instead.
- In backboardd they start right after the LA08 copied texture appears, then recur periodically; faulting command
  buffers often contain only `fixed_frag_lph_cph` (+ `attachment_clear_frag_lph`). The same shaders, LA08 contents,
  IOSurface render target, backdrop/vibrancy: **no faults in `ca`**. Not reproduced outside backboardd yet.
- Only backboardd imports IOSurfaces (the two framebuffers); app contents reach it otherwise (shared memory →
  buffers / linear textures, `newBufferWithBytesNoCopy` is copied, IMPORT_USERPTR unused by Mesa).

### Next steps (proposed)
1. Dump the faulting job: in backboardd via `vmg.env` enable a mode that, after each submit, waits and on a faulted job
   runs `pandecode_jc` on that chain only (Panfrost `PAN_MESA_DEBUG=sync` aborts; better a custom hook in
   `panfrost_batch_submit_ioctl` / vmg). Find which descriptor holds the garbage address.
2. Candidates to check: texture slots beyond the bound views (`set_sampler_views` count vs shader `textures_used`),
   samplers at 16+ (constexpr) vs bound sampler count, vertex attributes/buffers with a stale resource, blend
   descriptors when `nr_cbufs` differs, views (texture views / swizzle) of copied textures.
3. Then GPU frequency (`viva-link.py cmd gpu freq <MHz>`, table up to 950 MHz, now 300) for fluidity.
4. Fix `phase1` (sig 11) and `translate` (sig 6) crashes on the phone; `phase3` fails: baseInstance, two textures
   over one IOSurface (still), plain texture after IOSurface, fallback magenta, clear color; `uploads`: render
   into a level-1 view.

## How to work on the phone (no reflash)
- Link: `python3 ~/Developer/ios-viva/fork/tools/viva-link.py` (`log`, `cmd …`, `push LOCAL PATH MODE`, `pull`,
  `run -- [VAR=x] PROG ARGS`; `-o FILE` also records the kernel console in any mode). **One process at a time** on
  the USB link (else "Access denied"): stop the background logger before push/run.
- `run` of a missing program hangs forever (vivad never sends the end frame): no `/bin/rm`, `/bin/sync`, `sh`, `env`
  on iOS. `ps` (`/bin/ps`), `/usr/sbin/spindump`, `taskinfo` exist.
- **After `push`, wait ~45–60 s before `cmd reboot`**: the kernel's reboot does not sync; a file pushed right before
  is lost.
- Driver deploy: CI (`gh run …`, repo Nik300/viva-gpu, ~4 min) → `gh run download ID -n viva-gpu-ios` →
  push `VivaMTLDriver` (755) + `_CodeSignature/CodeResources` to `/System/Library/Extensions/VivaMTLDriver.bundle/`,
  tests to `/private/var/root/viva-tests/`. New processes (tests) pick it up immediately; backboardd needs a reboot.
- Variables for backboardd: `/System/Library/Extensions/VivaMTLDriver.bundle/vmg.env` (KEY=VALUE, `#` comments;
  backboardd cannot read `/private/var/root`). Now: all commented out.
- Diagnostics in the driver: `VMG_TRACE` (bindings, textures bound), `VMG_TRACE_NIR`, `VMG_TRACE_CB=1|2` (fragment
  shaders per command buffer), `VGPU_TRACE_BO=1` (BO GPU ranges), `TSMTL_LOG=1`, `VMG_HALF32`, `VMG_NO_ALIAS=1`
  (copy path on llvmpipe), `VMG_CA_SIMPLE=1` / `VMG_CA_IOSURFACE=1` (ca test).
- Symbolicate phone crashes: mount `~/Developer/ios-viva/ios16-root.img` read-only, then
  `ipsw dyld a2s <mnt>/System/Library/Caches/com.apple.dyld/dyld_shared_cache_arm64 --cache <scratch>/dsc.a2s --slide <slide from the CRASH line> ADDR`.
- Images: boot `out/xnu-ufs-rw-0109.img` (vivagpu=2), `out/xnu-ufs-rw-0109-quiet.img` (+ `sweetfb_noconsole=1`:
  no console text over the GUI, AMOLED); userdata `out/ios16-root-gpu2.simg` (old driver, then updated by push).

## For the kernel agent
- MMU faults come from userspace garbage pointers, not from the kernel (see above).
- Fault addresses are printed sign-extended.
- First-boot slowness after flashing userdata: lsd rebuilds the LaunchServices DB, SpringBoard waits on it
  (`__LAUNCH_SERVICES_IS_RESEEDING_ITS_DATABASE_AND_MAY_BLOCK__`), many minutes.
- `vivad`: a program that cannot be started never sends the end of reply.
- Link `reboot` does not flush the filesystem.
